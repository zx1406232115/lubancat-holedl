# 板卡系统安装指南 — 鲁班猫 1 (LubanCat-1 / RK3566)

> 本文档面向 Windows PC + 一块**还没装系统**的鲁班猫 1。
> 步骤依据野火官方文档整理，链接见文末。

---

## 第 0 步：先确认三件事（决定走哪条路）

在动手前，请先确认下面三点，这直接决定烧录方式：

### ① 板子具体是哪个型号？

鲁班猫 1 系列有好几个版本，**最大差别是有没有 eMMC**：

| 型号 | 存储 | 说明 |
|---|---|---|
| **LubanCat-1 / 1-V2** | eMMC（8～128GB） | 有 eMMC，可以烧到 eMMC，也可以烧到 SD 卡 |
| **LubanCat-1S / 1S-V2** | **无 eMMC，仅 SD 卡** | 只能用 SD 卡启动系统 |
| LubanCat-1N | eMMC | 软路由，双网口 |
| LubanCat-1 核心板（金手指/BTB） | eMMC | 只有核心板没有底板时，出厂不带系统 |

**怎么认**：看板子丝印上的型号字样。如果是 1S/1S-V2，就只能走 **SD 卡烧录**。

### ② 手上有没有这些硬件？

| 硬件 | 用途 | SD 卡方案 | eMMC 方案 |
|---|---|---|---|
| **Micro SD 卡**（8GB 以上，Class10 更好） | 装系统 / 当启动盘 | ✅ 必须 | 可选 |
| **读卡器** | PC 上写 SD 卡 | ✅ 必须 | — |
| **Type-C 数据线**（能传数据的，不是纯充电线） | USB-OTG 烧录 | — | ✅ 必须 |
| **5V/3A 电源**（Type-C 口，与 OTG 口共用） | 供电 | ✅ 必须 | ✅ 必须 |
| **网线** | 联网 + SSH | ✅ 强烈建议 | ✅ 强烈建议 |
| **USB-TTL 串口模块**（CH340 等） | 看启动日志、救砖 | 建议 | 强烈建议 |
| **HDMI 显示器 + 键盘**（可选） | 图形界面登录 | 可选 | 可选 |

> ⚠️ **Type-C 线一定要是数据线**。市面上很多 Type-C 线只供电不传数据，
> 用这种线烧录时会一直「发现不了设备」，这是最常见的新手坑。

### ③ 有 USB-TTL 串口模块吗？

强烈建议准备一个。板子的 Debug 串口默认参数是 **1500000-8-N-1**（注意是 1500000，
不是常见的 115200），在 Windows 上用 MobaXterm / SecureCRT / PuTTY 连上后，
能实时看到 u-boot 和内核启动日志。**系统起不来的时候，有没有这个日志，排查难度差十倍。**

## 推荐路线：SD 卡烧录（最简单，不需要装驱动）

如果你的板子是 1S/1S-V2，或者你不想在 Windows 上装 RK 的 USB 驱动，走这条。

### 准备工具

从野火百度网盘下载（链接见文末）：
- `SD_Firmware_Tool` —— 瑞芯微 SD 卡镜像制作工具
- `SDCardFormatter` —— SD 卡格式化工具
- 系统镜像：`lubancat-rk3566-<根文件系统>-<桌面类型>-<日期>_update.img`

**镜像怎么选**（文件名规则：`lubancat-处理器型号-根文件系统-桌面类型-更新日期_update`）：

| 字段 | 取值 | 建议 |
|---|---|---|
| 根文件系统 | `debian10` / `debian12` / `ubuntu22.04` … | 做本作业选 **debian12** 或 **ubuntu22.04**，apt 软件源新，装 gcc 方便 |
| 桌面类型 | `xfce` / `xfce-full` / `lite` | **`lite` 命令行版**最省资源、最稳，做作业完全够用 |

> 本作业只需要 gcc + make + bash，**建议直接选 `lite` 命令行版**，
> 体积小、启动快、跑起来不吃内存。

### 烧录步骤

1. **格式化 SD 卡**：把 SD 卡插进读卡器连电脑，打开 `SDCardFormatter`，
   选中你的 SD 卡，点 `Format`。
   （如果识别不到，先用 Windows 自带的格式化工具格一次 FAT32，再用它。）
2. **打开 `SD_Firmware_Tool.exe`**，确保 SD 卡已插入。
3. 在界面上：
   - **选择磁盘** → 选中你的 SD 卡（⚠️ 千万别选错成电脑硬盘！看容量确认）
   - **功能模式** → 选 **`SD启动`**
   - **选择固件** → 选中下载好的 `.img` 镜像
4. 点 **`开始创建`**，等进度条走完。
   - 镜像有几个 GB，烧录时间相应较长，耐心等。
   - 中途有概率弹错误框说无法烧录，**关掉错误框再点一次开始创建**即可（官方文档明确说明这是已知现象）。
   - 建议工具版本 **v1.74 以上**，低版本可能导致 Windows 蓝屏。
5. 烧录成功后拔出 SD 卡，插到板子的 TF 卡座。

### 启动

1. **如果板子有 eMMC 且里面已有系统**，需要让它从 SD 卡启动：
   通常是**不插 eMMC 启动跳线**或按住某个按键上电，具体看你的底板丝印。
   （1S/1S-V2 没有 eMMC，插卡上电即可。）
2. 接好网线、插上 Type-C 电源，板子开始启动。
3. 上电后等待 30～60 秒（首次启动会做分区扩容，会更久）。

## 备选路线：烧录到 eMMC（MASKROM 模式，最万能）

适用于：**板子完全没系统 / 系统坏了起不来 / 想把系统装进 eMMC**。
需要装瑞芯微的 USB 驱动。

### 准备工具

从野火百度网盘下载：
- `DriverAssitant` —— USB 驱动安装包
- `RKDevTool` —— 瑞芯微 USB 烧录工具

### 步骤

**1. 安装驱动 `DriverAssitant`**

解压后双击 `DriverInstall.exe`：
- 不确定以前装没装过旧驱动 → 先点 **`驱动卸载`**，再点 **`驱动安装`**。

**2. 打开 `RKDevTool`**

解压即用，双击 `RKDevTool.exe`。

**3. 让板子进入 MASKROM 模式**（关键步骤，别搞错顺序）

```
① 准备一根 Type-C 线，一端接电脑，一端先别插板子
② 断开板子上所有其它供电（电源线、其它 USB 线都拔掉）
③ 按住 MR 按键不松手（没有按键的型号用镊子短接 MR 孔）
④ 保持按住，先把 Type-C 线插进板子的 USB-OTG 接口
⑤ 再插上电源给板子供电
⑥ 等 RKDevTool 提示「发现一个 MASKROM 设备」
⑦ 提示出现后再松开 MR 按键 / 取消短接
```

- 如果没成功，重复 ②～⑦。
- USB-OTG 接口在板子上有 **`OTG`** 或 **`USB OTG`** 丝印，别插成 USB3.0 HOST 口。
- 有的型号（如 1N）是 **PWR 按键**，注意看丝印。

**4. 烧录固件**

1. 在 RKDevTool 里点 **`固件`** 标签页
2. 点右边的按钮选择 `update.img`
3. 等固件加载完成（下方会显示进度）
4. ⚠️ **开始烧录前必须松开 MR 按键 / 取消短接**，否则烧不进去
5. 点 **`升级`**，等待烧录完成
6. 出现成功提示即可断电重启

## 首次启动与登录

### 方式 A：串口 / HDMI 直接登录

板子上电启动完成后，会在串口终端或 HDMI 显示器上出现登录提示。野火官方默认账号：

| 用户 | 用户名 | 密码 |
|---|---|---|
| 普通用户 | `cat` | `temppwd` |
| 超级用户 | `root` | `root` |

> 首次登录后**建议改掉默认密码**：执行 `passwd`。

### 方式 B：SSH 远程登录（推荐，装完系统就这么用）

先确认板子 IP。三种办法：

1. **串口/HDMI 上直接查**（最可靠）：
   ```bash
   ip addr show            # 看 eth0 的 inet 地址
   # 或
   ip route get 1.1.1.1
   ```
2. **路由器后台**看 DHCP 客户端列表。
3. **网线直连 PC**，PC 上看新增的网卡网段。

拿到 IP 后，在 Windows 上：

```powershell
ssh cat@192.168.1.123
# 首次连接会问 yes/no，输 yes，然后输密码 temppwd
```

### 确认系统信息

```bash
uname -m            # 期望输出 aarch64
uname -r            # 内核版本
cat /etc/os-release # 发行版
df -h               # 磁盘空间
free -h             # 内存
```

## 开发环境准备

板子上装编译工具：

```bash
sudo apt update
sudo apt install -y build-essential
# 验证
gcc --version
make --version
```

`build-essential` 会把 `gcc`、`make`、`libc6-dev` 一起装上。
如果板子内存较小（1GB），编译本工程毫无压力（只有 4 个 .c 文件）。

## 把工程传到板子上

### 方式 1：scp（有网络时最方便）

在 **Windows PowerShell** 里，工程目录的**上一级**执行：

```powershell
scp -r E:\harnessproject\linux-homework cat@192.168.1.123:~/
```

### 方式 2：U 盘

板子插 U 盘，挂载后拷过去：

```bash
lsblk                          # 找到 U 盘设备，比如 /dev/sda1
sudo mkdir -p /mnt/usb
sudo mount /dev/sda1 /mnt/usb
cp -r /mnt/usb/linux-homework ~/
sudo umount /mnt/usb
```

### 方式 3：git（如果代码托管了）

```bash
git clone <仓库地址> ~/linux-homework
```

## 编译并运行

```bash
cd ~/linux-homework
make                       # 输出 ✔ 已生成 holedl (aarch64)

file holedl                # 确认是 ARM aarch64 可执行文件
uname -m                   # aarch64

make test                  # 31 项功能自测
bash tests/demo.sh         # 一键演示（会提示按 Ctrl-C 演示断点续传）
```

**截图建议**（作业要交「板端运行截图」）：

1. `uname -m` + `file holedl` → 证明是 aarch64 板端原生编译
2. `./holedl create big.bin 128M` 后接 `ls -l` 和 `du -h` → 证明空洞机制
3. `./holedl status big.bin --map` → 证明 status 功能
4. `demo.sh` 里 Ctrl-C 中断那一刻 + 续传完成 + `sha256` 一致 → 证明断点续传

## 常见问题排查

| 现象 | 原因 / 解决 |
|---|---|
| RKDevTool 一直「没有发现设备」 | ① Type-C 线是纯充电线，换数据线；② 顺序错了，必须**先按住 MR 再上电**；③ 驱动没装好，重装 `DriverAssitant` |
| 提示发现设备但烧录失败 | 开始烧录前**没松开 MR 按键/短接** |
| SD 卡烧录报错 | 关掉错误框重试；换 v1.74+ 的 `SD_Firmware_Tool`；先格式化 SD 卡 |
| 板子起不来、无输出 | 接串口看 u-boot 日志；确认 SD 卡/EMMC 里有系统；确认供电 ≥5V/3A |
| 串口全是乱码 | 波特率必须是 **1500000**，不是 115200 |
| `du` 显示空洞文件占用了空间 | 文件系统不支持空洞（如某些 FAT/exFAT 分区）。把文件建在 ext4 分区上，比如 `/home/cat` 或 `/tmp` |
| `make` 报找不到 `gcc` | `sudo apt install -y build-essential` |
| `download` 报「服务端不支持 Range」 | 那个服务器忽略了 `Range` 头。本工程会自动降级为顺序下载；要演示真续传请用 `tests/range_server.py` 或 `file` 本地源 |
| `ssh` 连不上 | 板子和 PC 要在同一网段；`ping` 一下；确认 sshd 在跑：`systemctl status ssh` |
